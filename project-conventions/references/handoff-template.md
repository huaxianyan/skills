# 进度记录模板与实例

主文件「开发进度文档」一节的展开。要建新项目或给已有项目补进度文档时读它。

## 单一时间线形态

适合长期项目。文件放 `docs/STATUS.md`，头部写清当前主线，正文按时间追加。

```markdown
# 实施状态

## 当前主线

<两三句话说明现在在做什么、为什么>

## STATUS-007：<本轮主题>

- 日期：2026-03-14
- 仓库：api `4f2c1ab → 91b0e77`
- 验证：`go test ./...` 全通过；真机走查 12 项全过
- 结论：<一句话>
- 边界：<没覆盖的部分>
- 下一步：<动作>
```

编号顺序递增，不要复用。倒序还是顺序都行，选定后不要来回换。

## 决策文件加日期流水

适合工作目录已被忽略的项目，例如 `.workbuddy/` 下的记录。

```text
.workbuddy/
  memory/
    MEMORY.md          # 长期决策，只有被推翻时才改
    2026-03-14.md      # 当日流水，追加
```

`MEMORY.md` 只放稳定结论：仓库定位、边界、定下来的决策、容易踩的坑。日期文件放当轮过程：试了什么、哪条路不通、最后落在哪。

## 写好一条的四个要求

### 写清验证强度

同一句结论，实测和推断的价值差一个量级。分开写：

- 实测：`六次独立复现，恢复时间 2.28 到 2.62 秒，分辨率 0.1 秒`
- 推断：`前台服务失效时的兜底作用未实测，属推断`

### 写清边界

至少回答一遍：样本多少、覆盖哪些平台、哪种条件没构造、结论在什么前提下成立。没有边界声明的结论，下一个执行者会当成普遍成立。

### 推翻旧结论时指名作废

```markdown
- 2026-03-18 实测否证条目 12 的推断：「豁免的价值是前台服务失效时的兜底」。
  反证：停掉服务后连接立即断开，且没有任何路径把它拉回来。
```

不写这一句，旧结论会一直躺在文档里被后人引用。

### 数字落地

`性能大幅提升` 没有交接价值。换成 `p99 从 120 ms 降到 40 ms，样本 2000 次`。

## 一条完整实例

```markdown
## STATUS-014：通知清除失败的判据修正

- 日期：2026-03-14
- 仓库：android `f1c60e6 → 1acef54`、extension `6ce265f → f4a6182`
- 现象：用户报「点了多次清除无效，手动划掉后浏览器侧才同步消失」
- 根因：判据用了 `isClearable`，它对单条取消的语义过宽；真正该判的是 `isOngoing`
- 改动：判据换成 `isOngoing`；失败原因不再被静默吞掉
- 验证：真机三个用例全过，其中 `FLAG_NO_CLEAR` 那条改前是 `INTERNAL_ERROR`，改后 `SUCCEEDED`
- 边界：只覆盖 AOSP 一台设备；厂商 ROM 的锁屏限制未测
- 下一步：等用户在日常使用中确认，无需再写测试
```

## 交接前自查

- 最新一条记录的日期是不是今天。
- SHA、分支、CI 结果是否现场核对过。
- 未完成项有没有写清阻塞条件。
- 凭据位置写了，但内容没写。
- 被推翻的结论是否已指名作废。
